# 本地粘贴 HTTP 接口设计

## 范围

为 Edge-Drop 增加一个可选的、仅绑定本机回环地址的 HTTP 服务。第一版
只支持文本内容，提供一个将文本加入当前面板历史的写入接口，以及一个返回
全部文本历史且包含完整内容的读取接口。对于持久化后只保留 300 字预览的长
文本，读取接口也必须返回完整内容。

该服务与系统剪贴板解耦：通过接口写入只会增加历史记录并更新面板，不会写入
操作系统剪贴板，也不会模拟 Ctrl+V。

## 配置

在持久化的 `Settings` 对象中增加：

- `pasteApiEnabled: boolean`，默认 `false`。
- `pasteApiPort: number`，默认 `18765`。

端口有效范围为 `1024..65535`（含边界）。设置规范化逻辑遇到无效值时恢复
为默认端口。设置页“行为”选项卡增加开关和端口输入框。用户启用、停用开关
或修改端口后，主进程自动启动、停止或重启服务。端口绑定失败不能导致
Edge-Drop 退出；服务保持停止，并通过现有的界面通知/日志路径报告失败。

服务必须绑定 `127.0.0.1`，不得绑定 `0.0.0.0` 或其他可被外部访问的网卡。
第一版不增加身份认证或 CORS 层，因为接口明确限定为本机回环访问。

## HTTP 协议

### `POST /paste`

请求头：

```http
Content-Type: application/json
```

请求体：

```json
{
  "content": "要加入的文本",
  "type": "text"
}
```

只接受字符串类型的 `content`，以及精确值为 `"text"` 的 `type`。空内容、
JSON 格式错误、字段缺失或其他类型都返回 HTTP `400` 和 JSON 错误对象。单条
文本的上限沿用现有 `ItemStore` 的 500,000 字符限制，超过限制时返回 HTTP
`413`。

成功后，处理程序必须沿用现有的文本历史存储路径，从而保留去重、命中次数、
捕获时间、历史数量上限、持久化和 renderer 更新事件等现有行为。成功响应为：

```json
{
  "ok": true
}
```

### `GET /list`

以下两个请求等价。未提供 `filter` 时默认使用 `text`：

```http
GET http://127.0.0.1:18765/list
```

```http
GET http://127.0.0.1:18765/list?filter=text
```

当前唯一接受的过滤值是 `text`；其他值返回 HTTP `400` 和 JSON 错误对象。

响应数组使用与面板相同的顺序，最新内容在前：

```json
[
  {
    "content": "完整的文本内容",
    "type": "text"
  }
]
```

响应只包含文本项目，并且每个项目只暴露 `content` 和 `type` 两个字段。对于
带有 `hasFullPayload` 标记的项目，处理程序必须调用 `ItemStore` 的完整文本
读取方法，从 `payloads/<id>.txt` 读取完整内容，不能直接返回 renderer DTO
中的预览字段。

### 通用错误

错误响应使用 JSON，并带有稳定的 `error` 错误码，例如：

```json
{
  "error": "unsupported_type",
  "message": "Only type=text is supported"
}
```

未知路径返回 `404`，不支持的 HTTP 方法返回 `405`。所有 JSON 响应都应设置
`Content-Type: application/json`，请求体读取应有大小上限，并在处理完成后关闭
请求。

## 架构与数据流

在主进程中使用 Node 内置 `http` 模块实现一个小型 HTTP 服务模块，不引入第三
方 HTTP 依赖，也不与 renderer IPC 耦合。该模块通过窄接口或回调依赖以下能力：

- 读取规范化后的设置；
- 通过现有 `ItemStore` 路径加入文本 `ItemData`；
- 读取当前 `ItemStore` 列表和完整文本；
- 成功修改后推送 `state:items`。

主进程在存储和窗口初始化后启动服务，并应用当前设置。设置更新继续使用现有
的 `settings:update` 处理逻辑，在设置保存并规范化后同步服务生命周期。应用退出
前关闭 HTTP 服务。

HTTP 协议不需要新增 renderer bridge 或 IPC channel。renderer 只需继续使用现有
的设置更新接口和设置事件来反映开关、端口变化。

## 校验与测试

增加以下聚焦测试：

1. 设置默认值和端口规范化。
2. `POST /paste` 的参数校验和文本写入成功路径。
3. 通过现有存储路径验证去重行为。
4. `GET /list` 的默认过滤和显式 `filter=text`。
5. 验证长文本项目从 payload 文件展开为完整内容。
6. 验证不支持的过滤值和内容类型会被拒绝。
7. 验证回环地址绑定、启动/停止/重绑，以及端口绑定失败不会导致应用退出。

实现必须保留当前存储语义：文件仍然只保存路径引用，图片不纳入本版 HTTP
协议，长文本继续使用现有 payload 文件保存。
